18 NOV 2026 · 4 MIN READ

Backups without storing data on a server

Expense Tracker keeps every transaction in SQLite on the phone. The only features that touch the network are backup and update checks. On Android I deliberately didn't build an account system or a server of my own — it uses the user's Google Drive. The web version uses Supabase.

The narrowest possible permission

The app only requests the drive.file scope. That means it can see and modify files it created itself, not the whole Drive. Because this scope isn't sensitive, the app skips a lengthy OAuth verification.

Two file formats

There's a monthly export (schemaVersion: 1) and a full-history snapshot (schemaVersion: 2). Both carry app and backupType fields that are checked on import — so a file from another app is rejected. Import also matches existing transactions so the same file never adds duplicates.

One operation at a time

SnapshotCoordinator uses a _busy flag to reject overlapping backups or syncs. Simple, but it prevents two processes from writing the same file on Drive.

The result on Android: no server for me to pay for, no user data for me to store, and the app still works offline. The web version uses Supabase for its demo data.
